# Discord コンシェルジュ型チケットBOT / VL-0004 ベース実装

Python 3.10以上、discord.py 2.7.1。実サーバーへの導入・接続試験は未実施です。

## 起動

1. `python -m pip install -r requirements.txt`
2. `.env.example`を参考に環境変数を設定してください。`.env`を自動読込する機能はありません。
3. `python bot.py`
4. サーバー管理者が `/ticket_panel` でパネルを設置します。スタッフは `/ticket` からも利用できます。

Discord Developer PortalでServer Members IntentとMessage Content Intentを有効にしてください。
招待時はbotとapplications.commandsスコープを使用します。BOTにはAdministratorを与えず、対象カテゴリでManage Channels、Manage Roles（権限上書きの管理）、View Channel、Send Messages、Embed Links、Read Message History、Attach Filesを与えてください。通常ログを使う場合、ログチャンネルでも閲覧・送信・ファイル添付を許可します。

## 環境変数

- `TICKET_ENV`: `test`でテスト用担当ロール、`production`で本番用担当ロール。未設定は既存動作を維持して`production`。それ以外は起動を中止します。
- `DISCORD_TOKEN`: BOTトークン。チャットやGitへ貼り付けないでください。
- `GUILD_ID`: 稼働するサーバー1個のID。
- `TICKET_CATEGORY_ID`: 新規チケットを置くカテゴリID。
- `STAFF_ROLE_IDS`: チケットを作成できるスタッフロールID。複数はカンマ区切り。必須です。
- `TICKET_LOG_CHANNEL_ID`: 通常相談のログ転送先。0または未設定で無効。
- `TICKET_DB_PATH`: SQLiteファイルの保存場所。バックアップとアクセス制限が必要です。
- `MAX_OPEN_TICKETS`: 相談者1人の同時チケット数。既定3。

担当ロールは仕様指定の10窓口を`DESKS`に登録済みです。スタッフの入力はEmbedに表示し、任意メンションの通知は抑止します。チャンネル名・トピック・監査理由には相談内容や当事者情報を含めません。

## プライバシーと第22条

- `@everyone`に閲覧拒否、BOT・相談者・担当ロールにのみ明示的な許可を付けます。カテゴリの上書きはコピーしません。
- 緊急相談の当事者は任意入力、1人まで。サーバー内のユーザーIDまたはメンションを使います。不明なIDは作成を止めます。
- 当事者個人には`view_channel=False`を設定します（`read_messages`の別名）。担当ロールの許可より個人拒否が優先します。
- **Discordの所有者・Administratorは権限上書きを無視できます。** 全チケットについてこの例外があります。当事者が該当する緊急相談は、内容を投稿せず作成を中止します。
- 緊急相談では担当ロール名を表示しますが、除外当事者への通知を避けるためロールpingを無効にしています。
- 緊急相談は共通ログへ転送しません。通常相談のログも、元チケットより閲覧範囲が広い場合は転送せず削除を中止します。Server Members Intentとメンバー一覧取得の権限が必要です。
- 共通ログに通常相談を集める場合、部門ごとの閲覧分離が崩れないよう注意してください。このベースは厳しい閲覧範囲照合を行うため、構成次第ではログ転送を拒否します。
- ログはテキスト・Embed内容・添付URLのみです。画像や添付ファイル本体は保存しません。添付URLの永続性は保証しません。
- ログ転送の失敗・容量超過時はチャンネル削除を中止します。ログ無効時、および緊急相談のCloseは内容を保存せず完全削除します。
- BOT自身・他のBOT・サーバー管理者からの閲覧を一律に防げる機能ではありません。管理者、権限編集者、BOT実行環境の管理者を信頼することが前提です。
- 作成後のロール変更・管理者昇格・権限の手動編集は新たなアクセスを生み得ます。本番ではDiscord側の権限変更監査も運用してください。

## 再起動・運用上の制限

作成パネルとCloseボタンは永続Viewです。相談先メニューと削除確認は短時間で失効します。
SQLiteはチケットID・相談者ID・窓口・除外IDを記録します。相談本文はDiscord内にだけ投稿します。
**単一BOTプロセスで稼働してください。** 複数プロセスの排他制御や高可用性は未実装です。
ネットワーク断やプロセス強制終了がチャンネル作成直後に発生すると、空のチャンネルが残ることがあります。カテゴリとSQLiteの照合を運用に含めてください。
カテゴリ上限、担当ロール消失、APIエラー時は利用者に一般的なエラーを返します。生の例外や相談本文を運用ログへ出しません。
SQLiteと閉鎖ログの保管期限・削除規程・バックアップは別途決定してください。

## 導入前チェック

- 通常相談：相談者と担当者は見える、無関係スタッフは見えない。
- 緊急相談：担当ロールを持つ当事者でも見えない。
- 緊急相談：管理者/所有者が当事者の場合は内容を投稿しない。
- 作成権限なし、無効ID、ロール消失、担当者不在時の拒否。
- Closeの権限、確認キャンセル、同時操作、ログ転送失敗時の削除中止。
- 再起動後のパネル/Close操作とSQLiteの保持。
- 全窓口の実ロールIDと対象カテゴリをテスト用サーバーで確認する。
